# Environment Configuration Guide

This guide explains all environment variables used in the Job Finder application and how to obtain the necessary credentials.

## Backend Configuration (.env)

The backend requires a `.env` file in the `backend/` directory with the following variables:

### Database
```
MONGODB_URL=mongodb+srv://user:password@cluster.mongodb.net/?retryWrites=true&w=majority
DB_NAME=job_finder
```

**How to get:**
1. **Local MongoDB**: If running MongoDB locally, use: `mongodb://localhost:27017`
2. **MongoDB Atlas (Cloud)**:
   - Go to [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)
   - Create a free cluster
   - Click "Connect" and copy the connection string
   - Replace `<password>` and `<username>` with your credentials
   - Replace `<database>` with your database name

### JWT (Security Keys)
```
JWT_SECRET_KEY=your_super_secret_key_change_this_in_production
JWT_ALGORITHM=HS256
JWT_EXPIRY_HOURS=24
```

**How to generate JWT_SECRET_KEY:**
```bash
# Using Python
python -c "import secrets; print(secrets.token_urlsafe(32))"

# Using OpenSSL
openssl rand -base64 32

# Using Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**Important:** 
- ⚠️ Change `JWT_SECRET_KEY` in production! Use a secure random string.
- Never commit the actual secret to git
- Keep it secure and rotated periodically

### Groq AI API
```
GROQ_API_KEY=your_groq_api_key_here
```

**How to get:**
1. Go to [Groq Console](https://console.groq.com)
2. Sign up/login with your account
3. Navigate to API Keys section
4. Create a new API key
5. Copy and paste it here

**Models available:**
- `mixtral-8x7b-32768` (default)
- `llama2-70b-4096`
- `gemma-7b-it`

### Telegram Bot
```
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here
```

**How to get:**
1. Open Telegram and search for `@BotFather`
2. Send `/newbot`
3. Follow the prompts to create a new bot
4. Copy the token provided
5. Save it in your `.env` file

**Optional:** To use the Telegram notification feature, save your Telegram Chat ID:
1. Send a message to your bot
2. Visit: `https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates`
3. Find your Chat ID in the response

### Server Configuration
```
BACKEND_URL=http://localhost:8000
FRONTEND_URL=http://localhost:5173
CORS_ORIGINS=http://localhost:5173,http://localhost:3000
```

**Explanation:**
- `BACKEND_URL`: URL where the backend is running (used for generating links, Telegram messages)
- `FRONTEND_URL`: URL where the frontend is running (used for CORS and redirects)
- `CORS_ORIGINS`: Comma-separated list of allowed origins for CORS. In production, use your actual domain(s)

**Production Examples:**
```
BACKEND_URL=https://api.example.com
FRONTEND_URL=https://example.com
CORS_ORIGINS=https://example.com,https://www.example.com
```

### Environment & Limits
```
ENVIRONMENT=development
DAILY_APPLICATION_LIMIT=5
```

**Explanation:**
- `ENVIRONMENT`: Set to `development` for detailed logs, `production` to minimize logs
- `DAILY_APPLICATION_LIMIT`: Maximum job applications per user per day

## Frontend Configuration (.env)

The frontend requires a `.env` file in the `frontend/` directory with the following variables:

### API Configuration
```
VITE_API_URL=http://localhost:8000
VITE_DEBUG=false
```

**Explanation:**
- `VITE_API_URL`: Backend API URL (must match `BACKEND_URL` from backend config)
- `VITE_DEBUG`: Set to `true` to enable debug logging in browser console

**Production Example:**
```
VITE_API_URL=https://api.example.com
VITE_DEBUG=false
```

## Security Best Practices

### 1. Never Commit .env Files
```
# .gitignore should include:
.env
.env.local
.env.*.local
```

✅ Already configured in the project

### 2. Use Environment Variables in CI/CD
For GitHub Actions, GitLab CI, or other CI/CD platforms:
- Set secrets in your repository settings
- Reference them in your CI/CD pipeline
- Never hardcode credentials

### 3. Rotate Secrets Regularly
- Change `JWT_SECRET_KEY` every 3-6 months
- Rotate API keys when team members leave
- Regenerate bot tokens if compromised

### 4. Use Different Secrets per Environment
- Development: Can be permissive
- Staging: Similar to production but isolated
- Production: Maximum security, strong secrets

### 5. Monitor API Usage
- Check Groq API usage in their console
- Monitor Telegram bot messages
- Set up billing alerts for cloud services

### 6. Database Security
For MongoDB Atlas:
- Create dedicated users (don't use master account)
- Restrict IP whitelist
- Enable encryption at rest
- Enable backups

## Troubleshooting

### Backend won't start - Missing .env variable
```
Error: GROQ_API_KEY: field required (type=value_error.missing)
```
**Fix:** Check `.env.example` and copy the variable to `.env`

### API requests failing with CORS error
```
Access to XMLHttpRequest from frontend has been blocked by CORS policy
```
**Fix:** Ensure `FRONTEND_URL` or `CORS_ORIGINS` includes your frontend URL

### Telegram notifications not working
```
Bot doesn't send messages
```
**Fix:** 
- Verify `TELEGRAM_BOT_TOKEN` is correct
- Check that user has Chat ID saved
- Ensure bot is running: `await telegram_bot.start_polling()` in main.py

### Groq API errors
```
Error: API key not found or invalid
```
**Fix:** 
- Regenerate API key in [Groq Console](https://console.groq.com)
- Ensure `GROQ_API_KEY` is set in `.env`
- Check that API key hasn't expired

### Frontend can't reach API
```
Network Error: Failed to fetch
VITE_API_URL not matching backend
```
**Fix:**
- Check `VITE_API_URL` in frontend `.env`
- Ensure it matches `BACKEND_URL` from backend `.env`
- Verify backend is running: `http://localhost:8000/health`
